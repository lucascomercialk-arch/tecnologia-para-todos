# 🌍 Guia de Internacionalização (i18n) — Tecnologia para Todos

Este documento descreve como o suporte multilíngue (**Português `pt`**, **Espanhol `es`** e **Inglês `en`**) está estruturado, como os textos e mensagens dinâmicas funcionam e como validar alterações com testes automatizados para evitar regressões.

---

## 1. Arquitetura dos Arquivos

| Arquivo | Responsabilidade |
| :--- | :--- |
| `js/i18n.js` | Motor de tradução (`TPT.i18n`): detecção inicial via `navigator.language`, persistência em `localStorage` (`tpt_lang`), interpolação `{variavel}`, fallback automático para `pt`, atualização segura do DOM via `textContent`/atributos e atualização de `<html lang="...">` (`pt-BR`, `es`, `en`). |
| `data/i18n/ui.js` | Catálogo central `window.TPT_TRANSLATIONS` com todas as strings visíveis da plataforma (`pt`, `es`, `en`), incluindo textos estáticos, labels de acessibilidade, erros de Python, status do worker e erros da API de Tasks. |
| `data/i18n/lessons-i18n.js` | Dicionário `window.TPT_LESSONS_I18N` com as traduções `es` e `en` de títulos, subtítulos, tópicos e cards das aulas (o conteúdo base `pt` fica em `data/lessons.js`). |
| `data/i18n/glossary-i18n.js` | Dicionário `window.TPT_GLOSSARY_I18N` com as traduções `es` e `en` de todos os termos do glossário, indexados pelo campo `term` de `data/glossary.js`. |
| `index.html` | Marca elementos estáticos com `data-i18n`, `data-i18n-placeholder`, `data-i18n-title` e `data-i18n-aria-label`, além do script inicial no `<head>` para definir `html[lang]` antes da renderização. |
| `js/app.js` | Aplica traduções nas abas, trilha de aulas e glossário (incluindo categorias como `Bibliotecas`). |
| `js/playground.js` e `js/pyodide-worker.js` | Traduz status do editor/console, código inicial padrão, nome do arquivo baixado e cartões amigáveis de erro (`translateError`, `messageKey`), re-renderizando erros ativos na troca de idioma. |
| `js/issues.js` e `js/tasks-api.js` | Renderiza status, módulos, prioridades, datas, exportação Markdown e erros HTTP/rede (`tasksApi.errors.*`) no idioma selecionado (Anti-XSS: zero `innerHTML` em `js/issues.js`). |
| `js/theme.js` | Atualiza `aria-label` e `title` do botão `#theme-toggle` quando o idioma muda. |
| `tests/i18n.test.cjs` | Suíte automatizada (Node.js puro) que valida paridade de chaves, placeholders `{var}`, atributos HTML, cobertura de aulas/glossário, Anti-XSS e comportamento em runtime. |
| `package.json` e `.github/workflows/ci.yml` | Scripts `npm test` / `npm run check:syntax` e workflow de CI executado em `push` e `pull_request` para `main`. |

## 2. Convenção de Identificadores (Namespaces)

Todas as chaves em `data/i18n/ui.js` seguem hierarquia em `camelCase` separada por pontos:

| Namespace | Escopo |
| :--- | :--- |
| `meta.*` | `<title>` e `<meta name="description">` da página |
| `a11y.*` | Textos de acessibilidade (`skipToContent`, `aria-label`, `title` do tema, link da marca) |
| `header.*` | Marca, subtítulo e nomes das abas principais |
| `home.*` | Hero, seção de propósito, cards de pilares, seção "Sobre Mim" e chamada final |
| `lessons.*` | Controles da Trilha de Aulas, progresso, botões e toasts |
| `glossary.*` | Cabeçalho, busca, contagem e tradução das categorias (`glossary.categories.*`) |
| `playground.*` | Botões do editor, console, status do Pyodide, separador decimal e `playground.errors.*` |
| `issues.*` | Formulário, filtros, badges, conexão, ações dos cards e mensagens da aba de Melhorias |
| `tasksApi.errors.*` | Mensagens de erro amigáveis de rede, rate limit (`429`), validação e permissão (`403`) |
| `footer.*` | Créditos e nota sobre Pyodide no rodapé |

## 3. Regras de Consistência Terminológica

| Conceito | Português (`pt`) | Español (`es`) | English (`en`) |
| :--- | :--- | :--- | :--- |
| Trilha | Trilha de Aulas | Ruta de Clases | Lessons Path |
| Aula | Aula `{n}` | Clase `{n}` | Lesson `{n}` |
| Glossário | Glossário | Glosario | Glossary |
| Botão principal do editor | Rodar Código | Ejecutar Código | Run Code |
| Botão de exemplo | Testar no Playground | Probar en Playground | Try in Playground |
| Terminal de saída | Console | Consola | Console |
| Variável | variável | variable | variable |
| Lista | lista `[ ]` | lista `[ ]` | list `[ ]` |
| Repetição | repetição / loop | bucle | loop |
| Indentação | indentação (espaços) | sangría (espacios) | indentation (spaces) |
| Comentário | comentário (`#`) | comentario (`#`) | comment (`#`) |
| Erro | erro (bug) | error (bug) | error (bug) |

> **Regra importante:** palavras-chave e funções nativas do Python (`print()`, `input()`, `len()`, `int()`, `float()`, `if`, `elif`, `else`, `for`, `while`, `append()`, `remove()`, `in`, `range()`, `import`, `random`, `time.sleep()`, `math`, `datetime`) **não são traduzidas** nos blocos de código nem nos identificadores de comandos, para que o aluno reconheça exatamente o que precisa digitar.

## 4. Fluxo de Manutenção para Contribuidores

### A. Adicionar ou alterar um texto da interface (HTML / JS)
1. Adicione a mesma chave em **`pt`**, **`es`** e **`en`** dentro de `data/i18n/ui.js`, mantendo exatamente os mesmos placeholders `{variavel}`.
2. No `index.html`, use:
   - `data-i18n="chave"` para textos internos (`textContent`);
   - `data-i18n-placeholder="chave"`, `data-i18n-title="chave"` ou `data-i18n-aria-label="chave"` para atributos acessíveis.
   - **Nunca** coloque HTML dentro das strings de tradução (todo conteúdo é inserido com `textContent`).
3. Nos scripts JS, use `TPT.i18n.t('chave', { variavel })`.

### B. Adicionar novas mensagens de erro ou notificações dinâmicas
- **Erros do Python (`Playground`):** adicione as chaves em `playground.errors.*` nos três idiomas em `data/i18n/ui.js` e trate o tipo em `translateError()` dentro de `js/playground.js`.
- **Mensagens do Worker (`Pyodide`):** envie `messageKey` no `postMessage` de `js/pyodide-worker.js` e garanta a chave correspondente em `playground.*` de `data/i18n/ui.js`.
- **Erros da API / Fila offline (`Tasks API`):** adicione a chave em `tasksApi.errors.*` nos três idiomas e use `t('tasksApi.errors.chave', fallbackPt)` em `js/tasks-api.js`.

### C. Adicionar uma nova aula ou novo card
1. Adicione a aula/card em `data/lessons.js` com `id` único (ex.: `aula-4`, `a4-def`).
2. Adicione a entrada correspondente em `TPT_LESSONS_I18N.es` e `TPT_LESSONS_I18N.en` dentro de `data/i18n/lessons-i18n.js` usando o mesmo `id` e mantendo a mesma quantidade de itens em `topics` e `items`.

### D. Adicionar uma nova palavra ou categoria no Glossário
1. Adicione o termo em `data/glossary.js`.
2. Se criar uma categoria nova, adicione `glossary.categories.<NomeDaCategoria>` em `pt`, `es` e `en` no `data/i18n/ui.js`.
3. Adicione a tradução indexada pelo mesmo `term` em `TPT_GLOSSARY_I18N.es` e `TPT_GLOSSARY_I18N.en` dentro de `data/i18n/glossary-i18n.js`.

### E. Adicionar um novo idioma (ex.: Francês `fr` ou Crioulo Haitiano `ht`)
1. Adicione o bloco completo do idioma em `data/i18n/ui.js`, `data/i18n/lessons-i18n.js` e `data/i18n/glossary-i18n.js`.
2. Inclua o código em `SUPPORTED_LANGS`, `HTML_LANG_MAP` e `normalizeLang()` dentro de `js/i18n.js`, além do mapeamento inicial no `<head>` de `index.html`.
3. Adicione o botão `data-set-lang="..."` dentro de `.lang-switcher` no `index.html`.
4. Atualize `EXPECTED_LANGS` em `tests/i18n.test.cjs` e rode a suíte completa de testes.

## 5. Testes Automatizados e CI

O projeto não depende de pacotes externos para testes. Com **Node.js 20+** instalado, execute na raiz do repositório:

```bash
npm run check:syntax
npm test
```

A suíte [tests/i18n.test.cjs](../tests/i18n.test.cjs) garante que:
- todas as chaves e placeholders `{variavel}` de `data/i18n/ui.js` possuem paridade completa entre `pt`, `es` e `en` e não há chaves órfãs;
- todos os atributos `data-i18n*` de `index.html` e todas as chaves literais `t(...)` / `messageKey` dos scripts JS existem nos três idiomas;
- não existem atributos `placeholder`, `title` ou `aria-label` sem marcação i18n em `index.html`;
- todas as aulas, tópicos, cards (`data/lessons.js`) e termos/categorias do glossário (`data/glossary.js`) têm tradução completa em `es` e `en`;
- `js/i18n.js` e `js/issues.js` mantêm zero uso de `innerHTML`/`outerHTML`/`insertAdjacentHTML`;
- o motor `js/i18n.js`, o sincronismo de tema (`js/theme.js`), os erros da API (`js/tasks-api.js`) e o tradutor de erros Python (`js/playground.js`) funcionam corretamente em `pt`, `es` e `en`, atualizando `<html lang="...">`.

Essas mesmas verificações rodam automaticamente no GitHub Actions a cada `push` ou `pull_request` para `main` (`.github/workflows/ci.yml`).
